hexo静态博客搭建与部署

2026-02-18
|
  • blog
hits
This article contains 1,983 words.

写一篇博客来介绍这个博客是如何搭建和部署的。

安装

需要准备的工具

  • nodejs 运行环境：hexo 静态博客依赖 node 环境
  • git 命令行工具：用于部署在 github 中，省略github的基本配置（如添加ssh-key、设置user.name 和 user.email）

仓库创建

创建两个仓库：

  • hexo_blog （名字随意），仓库用于存放博客的源码以及原始的markdown文档

    • 权限设置为private

  • 用户名.github.io （用户名为你github的用户名，后缀必须为github.io），用于存放博客页面

    • 博客网页需要给别人展示，所以权限设置为public

hexo 安装

新建 hexo_blog 文件夹，用于存放博客源码，在文件夹里打开命令行：

  • 安装hexo环境：
    • npm install -g hexo-cli
      • 安装成功后通过 hexo --version 查看版本
    • hexo init 在当前目录下初始化hexo环境
    • npm install 安装需要的node组件
    • hexo g 生成静态网页
    • hexo s 开启本地web预览页面，查看博客页面
      • 默认开启本地4000端口

  • 关联github上用于存放博客源码的仓库：
    • git init
    • git branch -M main 将本地主分支名修改为main，与github仓库中保持一致，如果github中默认的主分支被修改为master，此步骤可省略
    • git remote add origin git@github.com:username/hexo_blog.git username改成你使用的github用户名，需要先配置好github使用的ssh key
    • git pull origin main 从github仓库拉取文件
    • git branch --set-upstream-to=origin/main main 将github上的main分支和本地的main分支绑定

部署

经过之前的步骤，hexo博客在本地搭建成功了，下面介绍如何将博客部署到github页面上。

部署到github

  • 在博客目录下安装部署工具 npm install hexo-deployer-git --save
  • 修改博客目录下的_config.yml文件，添加需要部署的github地址（博客页面仓库，git@github.com/username:username.github.io）

  • 执行 hexo g 和 hexo d 将博客页面部署到github仓库中（需要配置github的ssh key）
  • 上述步骤完成后，访问 username.github.io 即可看到博客网页

主题更换

除了默认的博客主题外，可以在主题仓库中挑选喜欢的主题，并按照提供的步骤进行安装：

  • 官方主题仓库：https://hexo.io/themes/
  • 本博客使用的主题：https://github.com/Cerallin/hexo-theme-yuzu

安装步骤：

  • 安装主题与必要的依赖

  • 修改网站根目录下的 _config.yml。将 _config.yml中 theme字段改为hexo-theme-yuzu。将主题文件夹下_root_config_example.yml的内容添加到_config.yml中

  • 此主题比较简洁配置起来也比较方便

    • 设置博客的起始年份，会在页脚显示：起始年-当前年
    • 删除文章内容里的版权声明
    • 侧边栏一共有3种组件，可以修改页面上显示的名称和排列顺序：
      • Archives 按日期统计文章
      • Posts 按分类统计文章
      • Tags 按标签统计文章
    • 删除右上角的about菜单和页面下方的备案信息

  • 重新部署之后，页面如下（hexo clean && hexo g && hexo d），目前还有3处比较奇怪

    • 左上角的页面名称
    • 页脚的访问信息统计（PV是指访问次数，UV是指访问人数）
    • 页脚的作者名

  • 修改博客源码目录下的_config.xml，设置左上角的页面名称和页脚的作者信息

  • 修改 themes/hexo-theme-yuzu/layout/_partial/visit-count/site-container.pug，将PV修改为views，UV修改为visits

  • 点击页面上的tags标签时会出现404，通过查看主题仓库中的issue，解决方法如下：
    • 执行 hexo new page tags 命令，在生成的source/tags/index.md文件中添加 layout: tags

  • 网页的图标存放在 themes/hexo-theme-yuzu/source/img/favicon.ico，可以对其进行修改

文章发布

  • 将markdown和其同名的图片文件夹放到 source/_posts/ 目录下再进行部署，即可完成文章发布
  • 文章前面可以写一些元信息，用于标识发布日期、分类、标签、摘要等信息并显示在页面上
    • title 文章标题
    • date 发布日期
    • categories 文章分类，可以有多个（显示在首页对应名称的posts组件上）
    • tags 文章标签 ，可以有多个
    • 摘要使用more标签进行分割

  • 文章中使用图片
    • 修改博客源码目录下的_config.yml，将post_asset_folder设置为true
      • 编译后会将markdown和图片放入同一个文件夹内
    • 将图片放入 source/_posts/ 目录下与当前文章的markdown同名的文件夹下
    • 在文章中引用 ，此时生成的图片URL相对路径为 /文件夹名/图片
      • 默认情况下编译出来的博客内容URL为 年/月/日/文件夹名，因此此时图片无法正常访问，需要修改 _config.yml，将编译出来的博客URL改为 /文件夹名/

自动部署

手动部署依赖node和hexo-cli环境，自动部署只需要将博客的markdown文件push到博客源码仓库中就可以自动编译并上传到博客页面仓库，从而在username.github.io中显示。

  • 在本地创建用于部署的密钥对： ssh-keygen -t ed25519 -C "deploy-key-for-my-blog" -f "deploy_key"
    • deploy_key(私钥)
    • deploy_key.pub(公钥)
  • 将私钥复制后粘贴到博客源码仓库（私有仓库）

  • 将公钥复制后粘贴到博客页面仓库（公有仓库，仓库名为username.github.io）

  • 在本地博客源码目录下新建.github/workflows/deploy.yml，用于描述部署步骤
    • 将下面yaml文本中的 和，修改为你github实际使用的username和email（email前缀可以在github→settings→emails中查看，在页面中找到email后缀为@users.noreply.github.com的email前缀）
    • yaml文本中的 SSH_DEPLOY_KEY 需要和前面在私有仓库中添加secret key时取的名字相同（变为大写）

  • 执行下面的git命令，将博客源码同步到私有仓库，并触发自动部署。私有仓库页面的 Actions中可以看到正在执行的部署任务，点击进去可以看到部署过程中产生的日志。

    • git add * 添加所有博客源码
    • git add .github/ 添加部署说明文件
    • git commit -m "hexo init" 本地提交
    • git push 推送到github仓库，并触发自动部署

  • 之后只需要将新写的博客push到博客源码仓库中，就可以自动触发部署。部署逻辑为：

    • 本地博客源码目录push到远程的博客源码仓库中（私有仓库）
    • 私有仓库中按照.github/workflows/deploy.yml 步骤执行并部署到公有仓库（username.github.io）中
      • deploy.yml 中安装了hexo的node编译环境
